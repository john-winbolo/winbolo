## Lua editing (brains/GoalHunter/)
The active brain is **GoalHunter**. It has TWO copies of every Lua file:
- `brains/GoalHunter/*.lua` — base (dev) version with debug code, BRAIN_DEBUG_MODE branches, print2, viz calls, etc.
- `brains/GoalHunter/opt/*.lua` — stripped production version with debug blocks removed. Used by `--opt` runs AND by the WinBolo splash-screen background game (`bg_game.c`).

Rules:
- **Only modify the BASE files** (`brains/GoalHunter/*.lua`). NEVER hand-edit files under `brains/GoalHunter/opt/`.
- The opt/ tree is generated by a post-processing step (`lua_strip.exe`) from the base files. Direct edits there will be overwritten or cause base/opt divergence.
- After editing any base Lua file, copy it to the build directory so the running BrainTest/WinBolo picks it up:
  ```powershell
  Copy-Item "D:\Development\winbolo\brains\GoalHunter\<file>.lua" "D:\Development\winbolo\build\Brains\GoalHunter\<file>.lua" -Force
  ```
- Both `brains/GoalHunter/` AND `brains/GoalHunter/opt/` Lua files exist under `build/Brains/`. The base file copy is what's needed for default dev runs; `--opt` runs AND the WinBolo splash-screen bg_game read from `build/Brains/GoalHunter/opt/`.

### Regenerating opt/ (REQUIRED whenever the base file changes a stripped construct)

`lua_strip` removes any line beginning with `print2`, `viz.`, or `overlay_`, plus single-line `if BRAIN_DEBUG_MODE ... end` blocks. **Multi-line `if BRAIN_DEBUG_MODE ...` blocks break the stripper** — the first line gets stripped but the continuation `and ...` lines remain, producing a Lua syntax error like `unexpected symbol near 'and'`/`'then'`. Always write `BRAIN_DEBUG_MODE` conditionals on ONE line.

To regenerate opt/ after editing any base file:

```powershell
# 1. Build the strip tool (one-time, or after C-side strip changes):
& "<msbuild>" build/lua_strip.vcxproj /p:Configuration=Release /p:Platform=x64

# 2. Run the strip. strip.bat relies on cmd.exe globbing `*.lua`; under
#    PowerShell that wildcard reaches lua_strip literally and fails
#    ("cannot open '*.lua': Invalid argument"). Run it from cmd, OR expand
#    the glob yourself in PowerShell:
cd brains/GoalHunter
$files = Get-ChildItem -Filter *.lua | ForEach-Object { $_.FullName }
& "..\..\build\Release\lua_strip.exe" --strip print2 --strip "viz." --strip overlay_ `
    --strip-block "if BRAIN_DEBUG_MODE" `
    --exclude los_stamp_cache.lua --exclude shield_stamp_cache.lua `
    "$PWD\opt" $files

# 3. Copy results to the build's Brains dir:
Copy-Item "brains/GoalHunter/opt/*.lua" "build/Brains/GoalHunter/opt/" -Force
Copy-Item "brains/GoalHunter/*.lua"     "build/Brains/GoalHunter/"     -Force
```

If strip.bat reports `syntax error in stripped 'opt\<file>.lua'` it's almost always a multi-line `if BRAIN_DEBUG_MODE ...`. Fix the base file, re-run strip. The pre-built strip exe lives at `build/Release/lua_strip.exe`.

After any base-file edit that touches stripped constructs (print2, viz, overlay_, BRAIN_DEBUG_MODE), assume opt/ is now stale and regen + recopy before testing in WinBolo (which uses opt/ for the splash game).

## Build (C/C++)
- Use MSBuild.exe (NOT devenv.com which opens VS IDE)
- WinBolo: `MSBuild.exe build/WinBolo.vcxproj /p:Configuration=Release /p:Platform=x64`
- BrainTest: `MSBuild.exe build/BrainTest.vcxproj /p:Configuration=Release /p:Platform=x64`
- Add `/p:DebugInformationFormat=None /p:GenerateDebugInformation=false` to skip debug symbols (faster).
- "build" / "rebuild" = incremental. Only do clean rebuild if user says "clean rebuild".

## Logging
- print2 messages go to `debug_sessions/<TS>/print2_bot<N>.log`
- astar.log (one per session, shared across bots) for C-side A* per-step traces
- Lua files in build/Brains/ are loaded fresh each BrainTest run; C changes need rebuild.
