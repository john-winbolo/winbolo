KNOWN ISSUES
============

* The world-grid overlay starts from `originX - tileW - edgeX` and
  steps by gp/4*gp/tileW pixels.  At very low zooms the per-game-
  pixel lines may look too dense (a 1px line every gp screen pixels
  with gp=2 is 50% pixel coverage).  May want to skip the per-game
  level when zoomFactor < 3.
* The bases/pillboxes hitbox outlines are tile-centered ±128 wu
  squares.  Whole-tile hit logic actually tests the shell's tile
  index equals the entity's tile index, so the "true" hitbox is the
  whole tile — same screen rect as ±128 from tile centre.  Visually
  identical in practice.


NOTES & GOTCHAS
---------------

- AimTest tool from andrew-aim-test-old is NOT in main; reference
  only.
- The classic WinBolo render path uses screenBullets/screenStartXY
  (not mapViewRenderCentered which is BrainTest). Override mode
  must not break the classic path.
- The HUD layout is computed from the global `zoomFactor` (BYTE,
  values 1-4 + CUSTOM=0). Override-mode zoom up to 6x can't just bump
  that BYTE — would scale the HUD too. Need a separate
  worldZoomMultiplier or render-target redirect for the world view.
- tankIsTankHit uses |dx|, |dy| < 128 — that's the shell→tank hitbox.
  Pillbox/base hit logic is tile-based (pillsIsPillHit checks the
  shell's tile equals pill tile). So for the override yellow-box
  overlay:
    * Tanks: ±128 wu square
    * Pills/Bases: 1 tile (256 wu) square at the entity tile
- LGM viz from the source branch is in init.lua. For override mode
  the user wants this in C (HUD-independent, works regardless of
  bot brain). Plan to draw it C-side in WinBolo.exe's render path.
